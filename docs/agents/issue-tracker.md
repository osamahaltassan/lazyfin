# Issue tracker: Kaneo

Issues and specs for this repo live as tasks in the Kaneo project `Lazyfin`, key `LAZ`, on the Kaneo server named in `~/.agents/kaneo-url.md`. Use the `kaneo` CLI, already logged in on the maintainer's Mac, for every operation, and `kaneo api <method> <path>` for any endpoint it has no command for. `.kaneo.json` at the repo root links the clone to the workspace and the project, so inside the clone every command finds `LAZ` without `-p`.

A task is named by its key, `LAZ-<number>`. Every `kaneo` command takes the key, prints JSON when piped, and explains its flags with `--help`.

Pull requests stay on GitHub, through `gh`. Kaneo's GitHub integration stays off for this project, because it mirrors tasks into GitHub issues, which this repo no longer uses.

## Conventions

- **Create a task**: `kaneo task create "<title>" --description-file <file> --label "<label>"`. Write multi-line descriptions to a file first. A new task lands in `To do`.
- **Read a task**: `kaneo task view LAZ-<n> --full` for the description, relations, and every comment, or `kaneo task view LAZ-<n> --json`.
- **List tasks**: `kaneo task list --open --sort position` with `--status <column>`, `--label`, and `--assignee me` filters. `kaneo search "<words>"` finds tasks and comments by text.
- **Edit the description**: `kaneo task edit LAZ-<n> --description-file <file>`.
- **Comment**: `kaneo task comment LAZ-<n> "<text>"`, or pipe a multi-line comment on stdin.
- **Apply / remove labels**: `kaneo task edit LAZ-<n> --add-label "<label>"` / `--remove-label "<label>"`. Labels belong to the workspace; create a missing one with `kaneo label create "<label>"`.
- **Assign**: `kaneo task assign LAZ-<n> me`.
- **Close**: comment the outcome, then `kaneo task status LAZ-<n> done`.

The board's columns, by the slug commands take: `to-do`, `in-progress`, `in-review`, `done`, and `later`.

Agent-written tasks start with the line `> *This was generated by AI during a <skill> session.*` so a reader knows the author.

Tasks 1 to 22 came from the repo's former GitHub issues and keep their numbers, so an old `#7` in a commit or pull request means `LAZ-7`. `#14` to `#16` are pull requests and stay on GitHub.

## Wayfinding operations

Used by `/wayfinder`. The **map** is a parent task, and its tickets are its subtasks.

- **Map**: a task labelled `wayfinder:map`, holding the Destination / Notes / Decisions-so-far / Not-yet-specified / Out-of-scope body.
- **Child ticket**: a subtask of the map, created with `kaneo task create --parent LAZ-<map> ...`. Its body starts with the AI line. Labels: exactly one `wayfinder:<type>` (`research`/`prototype`/`grilling`/`task`) and nothing else. Kaneo shows the map's subtasks, so the map body lists no tickets.
- **Blocking**: `kaneo task relation add LAZ-<ticket> blocked-by LAZ-<blocker>`. `kaneo task relation list LAZ-<ticket>` shows a ticket's parent, subtasks, and blockers. A ticket is unblocked when every blocker is in `Done`.
- **Spec**: a task written by a `to-spec` session. Its opening paragraph links the map tickets it covers, and `kaneo task relation add LAZ-<spec> relates-to LAZ-<ticket>` ties it to each one.
- **Frontier query**: list the map's subtasks with `kaneo task relation list LAZ-<map>`, drop any in `Done` or `Later`, with an open blocker, or with an assignee; the one highest in the `To do` column wins.
- **Claim**: `kaneo task assign LAZ-<n> me`, the session's first write.
- **Resolve**: comment the answer, move the ticket to `Done`, then append a context pointer (gist + link) to the map's Decisions-so-far.

## Order of work

The board is the build queue. The order of open tasks in the `To do` column, top first, is the order the maintainer wants them built, across every map and standalone task. Kaneo keeps that order, and no task or doc repeats it.

- A wayfinder map is a parent task, and its tickets are its subtasks.
- The `Later` column holds tasks the maintainer has set aside on purpose. Each one has a comment saying what it waits for.
- The maintainer sets the order by dragging cards. The agent moves a card only when the maintainer gives it a place, such as for a new task or a reorder they ask for.

Done when the `To do` order matches the maintainer's, and every task set aside sits in `Later` with its reason.

The CLI has no command for a card's place. To set one, read the column top first with `kaneo task list --status to-do --sort position --json`, write the whole column in its new order to a file as `{"projectId": "<LAZ project id>", "tasks": [{"id": "<task id>", "position": 0, "status": "to-do"}, ...]}`, and send it with `kaneo api POST /task/reorder --input <file>`. `kaneo project view LAZ --json` prints the project id.

To set a task aside, `kaneo task status LAZ-<n> later` and comment what it waits for.
